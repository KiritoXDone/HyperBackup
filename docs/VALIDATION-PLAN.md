# 完整业务覆盖与发布验收

状态：r2。用户已确认正式首版必须完整覆盖固定上游；开发可分阶段，部分结果只能作为预览。本文是验证要求，不等于当前结果报告。

## 阶段

| 阶段 | 交付 | 退出条件 |
| --- | --- | --- |
| P0 完整引擎与宿主 | 完整工具、窄桥接、Root、稳定操作映射、原生备份根 | 实际调用上游业务路径；不依赖安装/唤起原 SpeedBackup；单应用双向恢复与未知结果保护通过 |
| P1 配置与业务闭环 | 应用/系统/用户、压缩/名单、AppState、文件夹/其他数据、所有源配置 | 每组入口、参数、默认值、结果与平台限制可追溯 |
| P2 远端/维护 | 两类传输/恢复模式、发现追踪、上传/清理/测速/修复、执行辅助 | 正常与失败分支通过，保留 upstream 限制，不用简化流程代替特殊路径 |
| P3 UI 与交互 | 原有 Miuix 外观、完整能力导航、特殊账号/用户映射、任务状态 | 能力不藏在仅开发可用命令中；高级功能有可用原生入口和说明 |
| P4 上游跟进与正式发布 | 差异审查、配置/能力快照、版本锁、兼容和故障报告、许可证 | 覆盖矩阵全部必需项有证据；未分类变化或未完成业务阻断正式版 |

原精简路线的 Root/任务/UI/CI 可复用，专用容器及业务重实现不能据此被认定为完整覆盖。不能把 submodule、编译成功或全按钮截图当作业务完成证据。

## 每项能力的证据

UPSTREAM-PARITY.md 的每个 ID 都需关联：
- 实际入口、operation ID、配置字段/值/默认值、目标上游执行分支。
- 实现提交、输入夹具、预期副作用与限制、实际结果和测试环境。
- 正常、可预期拒绝、失败/中断、再次进入/恢复后的检查。
- 支持的上游 SHA 和 App 版本；引擎/格式/默认值变化会使旧证据需要重新评估。

机器级清单与差异检查由实现补齐。当前 Markdown“待核验”不是单方面否定活跃代码，而是要求将完成证据登记后再改变状态。

## 双向互操作是硬门槛

| 方向/变化 | 必须证明 |
| --- | --- |
| 原脚本→HyperBackup | 当前及该版本支持的本地旧格式能识别、选择和恢复，缺 App 索引/hash 不造成伪损坏 |
| HyperBackup→原脚本 | 原脚本可扫描 App 产物、读取 metadata 并恢复；不是只证明 tar 可解压 |
| 删除 App 附加数据 | 原备份仍能恢复，App 可重建索引，不丢业务内容 |
| 新建第二集 | 第一集保持原样，后缀冲突正确处理，不跨集写入 |
| 更新已有集 | fast-skip 对相同集正确生效，新增/变化内容正确更新，批次历史不冒充旧内容版本 |
| 本地/SMB/WebDAV | metadata bundle、目录、特殊载荷、上传/统计/清理一致 |
| 前一支持上游→新候选 | 声明兼容范围的历史样本恢复通过，未知格式不猜测覆盖 |
| 原始脚本外部更新/删除 | 检测附加索引/摘要失效；并发未知时阻断危险操作 |

备份产物、路径和 metadata 需要语义对照，不要求压缩时间戳等不可重复字节完全相同。比较包括文件内容、类型/链接、权限/属主/标签、对象选择、原有排除和失败保留范围。

## 业务重点用例

- 普通和白名单系统应用；APK-only、CE/DE/外部数据、空/缺失/排除、split 完整性。
- 主用户/分身同包名；用户锁定/删除发生在预检后；来源 UID 不直接用于目标。
- 应用稳定 guard、Background_apps_ignore、黑白名单两模式、特殊宿主保护与收尾。
- 只备份已更新应用，版本不可比较；本地和两种远端的逐项/整批 fast-skip。
- 全压缩配置范围、小文件参数、媒体 tar 规则，不能硬编码成单组 zstd 参数。
- APK 同版/本机新版/明确更新失败/首次安装失败/UID 失败/未知75；Play 身份和低 target SDK 开关；仅恢复未安装应用。
- AppState 全子项及只恢复状态；未知能力明确报不支持，不用“尽力”吞掉未接入项。
- Wi-Fi 单独/关联/远端恢复及失败保留；SMS/MMS/通话合并、重复跳过、默认备份/恢复差异及世代保留。
- Maps 普通数据与 Timeline 分开；账号映射、合并、延后恢复和局部失败收尾。
- thanox/HMA-OSS 额外路径与标签/重启说明；自定义目录、挂载排除、KSU /data/adb 禁止条件。
- 直接流式备份、先本地后上传、逐应用上传、保留/删除本地包、单独上传已有内容。
- 下载后恢复与直接串流恢复；下载/传输中断、部分写入、无可信历史 hash、保护副本失败。
- SMB/WebDAV 发现、共享选择、设备身份/换址、凭据重填、HTTP显式选择、TLS拒绝和两方向测速。
- 本地/远端孤儿候选、手动删除、日志清理；统计/归档与JSON检查、metadata重生、旧目录名转换。
- 低电量策略、亮屏伪装、后台/通知选项；远程电脑关机资格、倒计时取消和错误处理。
- 简繁配置及消息、实时/历史日志、诊断脱敏、自检与组件版本不一致。

高影响测试在专用可丢弃测试应用、目录、Android 用户或授权测试服务器中进行。通信记录、Wi-Fi、账号、系统目录及远程关机不能拿用户真实数据/工作电脑作为默认夹具。无法实测的真实环境明确列限制；不能将未接入功能标成“设备限制”通过。

## 故障与生命周期

双击/重复 intent、响应丢失、取消与完成竞态、UI退出/重建、Binder失联、daemon/native被杀、Root撤销、系统Stop、App升级、设备重启分别验证。任务先对账，不自动重放可能已经提交的安装或覆盖操作。

网络中断、容量未知/不足、USB拔出、坏归档/路径穿越/跨挂载、未知metadata、远端换身份、源并发写入、发布/删除中断、收尾失败分别注入。记录已写入范围，保留上游局部事务含义，不宣称全局回滚。

App 的保护副本、保守停止、HTTP显式选择等控制差异单列测试；不能用新增保护阻断源本来提供的整个业务模式。直接串流不应显示下载模式专属的“覆盖前全文校验通过”。

## 上游升级与 UI

对菜单插入导致 ID 位移、字段默认值改变、capability 增删、特殊格式变化、工具更新剪裁、原宿主安装路径和补丁冲突建立回归。更新只激活成套已验证 APK/引擎，不混搭源版本。

UI 复用既定 Miuix 风格，核对四入口及高级功能、明暗/字体1.0–2.0、48dp触控、TalkBack、键盘/系统栏/横屏、长列表和多用户选择。没有 trace 不报告帧率；图稿不等于交互验收。
