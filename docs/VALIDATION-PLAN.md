# 开发顺序与验收标准

这是后续实现的验证计划。本次仅完成研究、设计访谈、ADB 页面观察和概念图；未编译新 App、未执行备份或恢复测试。

## 里程碑

| 阶段 | 交付 | 退出条件 |
| --- | --- | --- |
| P0 引擎可行性 | 固定工具构建、Root 桥、类型化单作业、结构化结果 | 使用可丢弃测试 App / 用户跑通本地备份与恢复，不依赖脚本菜单点击；验证安装未知结果不重放 |
| P1 格式与本地闭环 | 多批次仓库、清单/hash/提交、Room 重建 | 两个版本互不覆盖；重新安装后可发现；损坏和半写产物不被当完整备份 |
| P2 远端与保护 | SMB/WebDAV、逐应用暂存、恢复前副本 | 断网、凭据失效、空间不足与提交响应丢失可解释；副本失败不覆盖 |
| P3 UI 与任务体验 | 已确认 Miuix 页面、明暗主题、任务接回、错误引导 | 主流程与异常流程均走通；没有重复提交、虚假进度或失联成功状态 |
| P4 发布准备 | 支持矩阵、许可证/对应源码、诊断脱敏、升级兼容 | 固定版本回归通过，明确未支持环境和数据限制 |

P0 失败时调整适配边界并更新 ADR，不靠 UI 模拟成功掩盖引擎缺口。上游修改、新增桥接、格式写入、App 页面分开变更，便于核查行为差异。

## 核心场景

| 场景 | 必须观察到的结果 |
| --- | --- |
| 主用户和分身同包名 | 独立条目/归档/选择；目标用户明确；不串数据 |
| 用户锁定/移除发生在预检后 | 写入前重查；准确阻断/停止，不凭旧 UID 继续 |
| split APK 应用 | 完整集合与一致版本/签名；缺 split 在修改前提示 |
| 运行中应用 | 按上游 auto guard / 停止策略处理；无法静止有数据跳过结果，收尾有证据 |
| 黑名单 APK-only / 整应用跳过 | 计划、执行、UI 三者一致，不报告所有数据已保存 |
| 上游固定排除目录 | 清单可追溯，恢复不假定被排除内容存在 |
| 同应用再次备份 | 新 record/batch，旧版本内容及 hash 不变 |
| 手机重装 App 后添加仓库 | 无旧 Room 数据仍可重建本格式索引；凭据重新配置 |
| 相同包名不同来源设备 | 来源可区分；不自动认为是当前设备的新备份 |
| 副本来自旧 App 版本 | 按脚本保留较新现有安装；数据恢复风险和实际行为分开显示 |
| 签名冲突导致明确更新失败 | 测试夹具验证现有安装有效时继续数据的脚本分支；分项结果不被成功摘要吞掉 |
| 新安装失败 / UID 查询失败 | 不恢复对应数据/AppState |
| PM commit 结果未知 75 | 整批停止、无自动重试、无继续数据写入，重开页面仍待确认 |
| 保护副本上传失败/提交未知 | 对应目标应用尚未覆盖，能定位原因与清理状态 |
| 归档篡改、截断、非法路径/链接 | hash/结构/路径检查在目标写入前失败；不能写到目标根之外 |
| 超大解包声明/压缩炸弹 | 存储预算/展开上限阻断，旧应用未被提前清空 |
| 恢复中途解包失败 | 必须收尾属主/权限/标签与保护状态；报告部分写入，不宣称回滚 |
| 仅应用状态恢复失败 | 相应状态项目显示失败/不支持，文件成功证据保留 |

## 生命周期与存储故障

| 注入 | 验收 |
| --- | --- |
| 双击开始、旋转、重复 intent、Binder 回应丢失 | 同 requestId 不产生第二次执行；payload 冲突被拒绝 |
| UI 退出、App 重建、通知重新进入 | 返回同一任务；先检查 boot/process 身份再接回 |
| 设备重启、Root 被撤销、系统 Stop、进程 kill | 区分中断/未知；无重放恢复；检测残留冻结/临时文件并记录收尾结果 |
| FGS 超时 / WorkManager 配额限制 | 遵守系统要求并安全收尾/对账；不以调低 target 为产品策略 |
| 提交、上传、发布清单、删除过程中断网 | 不造假完成、不覆盖重传、不误删其他记录；不完整条目不可恢复 |
| NAS 只读、密码错误、TLS 错误、容量未知 | 错误分类明确；无协议降级/忽略证书；没有自动换目录 |
| 换 IP 后连接到不同仓库 | repoId 不符阻止继续旧操作 |
| 另一设备持有写声明 / 声明未知 | 当前修改阻止；不仅凭心跳超时抢锁 |
| 本地满、远端满、USB 拔出 | 任务停止并保留可解释状态；已有已提交备份不受影响 |
| 删除任务中断 | 被删除条目不伪装完整；残留可被有记录地清理 |
| 引擎更新发生在任务中 | 版本锁阻止替换；升级后旧日志仍能按对应协议读取 |

## UI 验收

以实际 Miuix 组件和手机截图比对，不能将生图视为像素规范。核对四入口、展开/折叠标题、安全区、选择工具条、长名称、TalkBack、深色与大字体。真实扫描 1000 项时观察重组/滚动；未经 trace 不报告具体帧率。

首次授权失败、空列表、无备份、网络离线、恢复冲突、部分完成、结果待确认、停止收尾、无可重试项目都需要实际可到达的页面状态。

## 发布证据

报告分为源码/API 核对、编译/静态检查、契约与故障测试、设备备份/恢复、视觉无障碍、性能六类。Android 9 与最新测试系统、不同 Root 方案及 NAS 实现分别列结果；只在某一设备通过不扩写为全版本兼容。

先使用专用测试包和可丢弃数据，覆盖数据库、CE/DE、外部目录、不同版本/签名的夹具。真实个人应用试验需单独安排，不属于本次设计任务。恢复后的验证不仅看 exit code，还检查内容、应用启动、用户归属、权限和已声明核验范围。
