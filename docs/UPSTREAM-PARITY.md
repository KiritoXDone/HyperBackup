## 一行不等于一个按钮或一个测试

每行完成前，需登记实际 App 入口、稳定 operation ID、涉及配置键/值/默认值、上游执行入口、平台条件、输出/错误契约、实现提交、测试证据及支持 SHA。细分必要子案例：例如 CAP-14 至少区分 SMS/MMS/通话、备份/恢复、重复合并与跨用户；CAP-16 区分普通 Maps 应用数据与 Timeline 特殊流程。

后续建议使用可校验的机器清单承载这些字段，Markdown 由其生成；新增字段或菜单不能自动标为已覆盖。状态建议为“待核验 / 实现中 / 已接入待验证 / 已验证 / 回归失败”；所有必需行及子项验证完成才可发布正式版。

## 明确的映射与差异

- 上游原 APK 的启动/返回/签名校验改为 HyperBackup 宿主适配；宿主差异不算业务功能删除，但要测试不能安装或拉起错误 App。
- 更新分发经用户明确选为随 APK 发布；不照搬会覆盖工具并安装 SpeedBackup 的原始自更新行为。
- 新建/更新备份集都提供，默认新建。更新模式才有既有集作为 fast-skip 比较对象；新建不伪称完整沿用了跳过优化。
- App 仍默认下载后恢复、提供可选恢复前副本、未知结果对账；直接串流恢复不能因缺少 App 专属 hash 被永久禁用。新增保护与限制在确认页说明，不能掩盖源模式差异。
- KernelSU Miuix 外观、橙白图标与四主入口保留。上游壁纸/玻璃/背景动画未列入业务覆盖；简繁语言与可读日志仍要覆盖。

## 不能从“完整”推导的承诺

本次未证实独立联系人导入导出、用户级排程、通用归档口令加密、块级去重、任意断电续传或整批恢复回滚。不得虚构这些上游能力，也不能把局部 Timeline/下载交易扩大为全局事务保证。

性能优化和安全机制虽不都需要按钮，也不能被复用部分工具的简化流程静默丢掉。前台正常退出、任务中断、磁盘/网络错误、安装未知结果、源配置迁移和所有特殊数据路径均是覆盖证据的一部分。
