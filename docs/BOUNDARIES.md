# 正式首版范围与行为边界

状态：2026-11-08 设计修订 r2。用户已将正式首版目标改为完整覆盖固定版本脚本的业务能力，并确认双向格式兼容与验证后随 APK 更新。本文替代原精简范围；能力尚未实现或未验证时不能声称已支持。

## 覆盖原则

目标基线为 backup_script v1117 / 4d85ef6f974dc8b4a9208dd2aa9578a3d69e1ab5。完整覆盖包含用户入口、配置值/默认值、执行效果、失败分支、平台限制及诊断能力；不是只装入几份二进制或把菜单画全。

正式版的能力入口和行为以 [覆盖矩阵](UPSTREAM-PARITY.md) 为核验目录。未完成项是预览版缺口，不能重列为正式首版排除。新增源能力须补矩阵，不能以当前列表为永久上限。

| 能力组 | 正式首版要求 |
| --- | --- |
| 普通/系统应用、APK/splits、CE/DE、外部 data/OBB/media | 按上游选择、白名单、归档及恢复规则覆盖 |
| Android 多用户/分身 | 明确来源和目标，保留用户和平台限制 |
| SSAID、权限、AppOps、特殊访问、电池策略 | 记录、恢复、验证及独立 AppState 模式均覆盖 |
| Wi-Fi、SMS/MMS、通话记录 | 覆盖单独/关联入口、合并/去重、默认值及 Provider 限制 |
| 自定义目录、Maps Timeline、thanox/HMA-OSS | 覆盖实际特殊流程，不能用普通应用归档代替 |

| 远端/本地清理、统计、检查与修复 | 保留候选确认、日志/特殊数据保留及失败语义 |

平台基线仍为 Android 9+、arm64、Root，Magisk/KernelSU 按上游声明及实际验证范围报告。系统应用不等于系统分区镜像，也不等于任意 ROM 配置都可迁移。

## 新建与更新备份集

同时提供两种操作，默认“新建备份集”：
- 新建：选择一个唯一的上游兼容备份根，保留之前的备份集。
- 更新：明确选中已有备份集，允许上游修改它，并使用其 fast-skip、版本比较与已有产物判断。

空的新备份集不能因为另一备份集没有变化而省略所需内容。不得同时声称“每次新建独立完整历史”与“零复制继承上游跳过”，除非另有经过兼容验证的实现。更新已有集不是新增历史版本；任何清理规则都要说明作用于哪一集、哪一数据类别。

## 应用保护和安装

业务规则由完整的固定版引擎负责，App 不另写一套“看起来相似”的处理。
- 运行中应用沿用 Background_apps_ignore、cgroup auto guard、停止与可选暂停策略；不安全数据项可跳过，收尾释放保护后才报告完成。
- 黑名单两种模式、白名单、system 列表、APK-only 例外都保留。
- HyperBackup 新宿主必须显式加入自身保护；不能用笼统禁用系统应用代替适配。
- 当前未安装时安装/关联包；备份版本更高时尝试更新；同版、本机版本更高或不可比较时可跳过 APK 后继续数据。
- 更新明确失败但现有安装/UID 有效时，原脚本仍可能继续数据；界面分开记录安装失败和数据结果。
- 首次安装或 UID 确认失败时不写数据；安装提交结果未知 75 时不得重试或继续该应用数据/AppState，并按 App 对账策略停止本轮。
- 保留 Play 安装者、低 target SDK 可选策略、仅恢复未安装应用等实际分支；不新增自动卸载/强制降级。
- 记录上游排除规则及特殊应用路径，不能将全部路径差异概括为“仅排除缓存”。

所选功能仍受设备权限、Provider、用户解锁、系统版本和上游限制约束。例如自定义 /data/adb 分支在 KSU 下受上游限制；不应宣传成通用 Root 模块迁移。

## 远端恢复与完整性

默认先下载再恢复，也必须提供上游直接串流恢复。两者清楚列出空间和检查范围，不因空间不足自动替用户切换模式。

下载模式可在覆盖前核验完整本地归档；原脚本备份没有 App hash 时，使用上游结构/清单检查，不能假装已有可信历史摘要。串流模式保持上游检查和失败收尾，不能承诺完整归档 hash 在覆盖前通过，也不承诺整批回滚。

应用恢复前副本默认开启，可明确关闭。副本需覆盖实际将改动的内容，保存未确认成功时不覆盖；其他数据类型按其上游原有保护/合并语义处理，不能外推为全部对象自动回滚。

## 存储、配置与更新

- WebDAV 默认 HTTPS；HTTP 显式可选并标示未加密。证书错误不自动忽略。SMB 能力按协商结果报告，不能默认宣传传输加密。
- 配置的业务含义、可用值、默认值和迁移规则来自固定上游；App 保存 UI 偏好、凭据保护引用和任务投影，不维护第二套互相漂移的执行配置。
- 远端换址只在上游确认设备身份的条件下使用；不能在进行中的任务中自动换目的地。
- 更新检查/获取/验证的目的通过 HyperBackup 的已验证 APK 版本实现。用户已选择随 APK 更新，不把原始脚本 ZIP 直接覆盖到运行工具目录，也不安装/唤起原 SpeedBackup 作为新 App 的操作入口。
- App 修改型任务互斥；同一备份集的并发更新/删除和原脚本外部修改需检测。不能声称原脚本会遵守 App 私有锁，恢复和修改前重新核对数据。
- 凭据不进入导出日志/附加索引。归档加密与传输保护区分，源未提供的归档加密不由“完整移植”推导出。

## 不应误算为缺失的能力

目前未找到独立联系人导入导出、用户级定时备份、通用归档口令加密、块级去重或任意断电自动续传/整批回滚的充分上游证据。这些不是本次完整覆盖凭空新增的承诺；未来上游新增后进入同一差异审查。

原脚本有通信记录特定世代保留、日志容量清理和孤儿备份清理，必须覆盖；它们不等于通用多版本保留策略。外观特效明确不属于本次业务能力覆盖范围。
