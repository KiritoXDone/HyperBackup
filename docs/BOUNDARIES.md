# 首版范围与行为边界

产品决定与工程默认值已于 2026-11-08 经整体 v1 评审确认。所有“支持”均为目标范围，设备验收前不得作为已验证承诺。

## 范围矩阵

| 能力 | 首版 |
| --- | --- |
| 独立 APK，桌面启动、App 内申请 Root | 包含 |
| Android 9+、arm64，Magisk / KernelSU | 沿用脚本基线；其他方案只记为待测 |
| 普通应用 APK / split APK、CE / DE 私有数据 | 默认包含；目录排除规则以引擎为准 |
| Android/data、Android/obb、Android/media | 可选，不把共享目录中的所有文件都归属给某应用 |
| SSAID、权限、AppOps 等应用状态 | 尽力记录；高级恢复显式启用，默认关闭，逐项报告能力与结果 |
| 多 Android 用户、分身 | 明确来源和目标，按用户区分应用；不自动创建用户或绕过资料策略 |
| 本地路径、SMB、WebDAV | 包含；本地限引擎可访问的实际路径，挂载盘逐介质验证 |
| 多次独立备份、手动删除 | 包含 |
| 逐应用下载校验后恢复 | 包含；不足以暂存当前应用时阻断 |
| 恢复前备份 | 默认开启，可显式关闭；副本失败不覆盖该应用 |
| 任务记录、当前会话接回、重新检查未完成项 | 包含；无断电后自动续写保证 |
| 系统应用、Wi-Fi、短信/联系人、任意共享文件夹 | 不包含 |
| 自动排程、自动保留、去重引擎、自动远程发现 | 不包含；手动配置目的地 |
| 旧脚本 / DataBackup 格式导入、其他云盘协议 | 不包含；只支持新 App 格式重新扫描 |
| 归档口令加密、远端直接串流恢复 | 不包含 |
| 通用 SAF 文档提供者 / 网盘 Content URI | 首版不承诺；不能将其伪装为普通磁盘路径 |

## 按脚本继承的应用保护规则

基线固定为 backup_script v1117 / `4d85ef6`。用户明确要求停应用与安装策略按脚本执行，不采用访谈中曾推荐的“一律停止”“一律阻断降级情形”。

- `Background_apps_ignore=0`：默认不因应用运行中就跳过；启用该选项时，运行中应用会跳过。
- cgroup guard 默认 `auto`：部分高风险/候选应用先尝试冻结，其余按引擎停止流程处理。可选进程暂停默认关闭。仍无法静止时返回相应原因，跳过不安全的数据项；APK/metadata 结果单独记录。
- 默认黑名单模式是只保存 APK、跳过数据；可设为整应用跳过。默认名单没有启用项。APK-only 模式的例外规则沿用引擎，不用 UI 猜测。
- UI 必须在执行前说明应用可能暂时被冻结或关闭；保护收尾完成后才结束对应项目，不保证重开 force-stop 的应用，也不宣称恢复第三方冻结工具的全部历史状态。
- 新 App 包名需要明确加入宿主保护；上游现有 MT / Termux 检测不会自动识别新宿主。维持任务所需的 Root 管理组件亦从本作业写入目标中排除，此为独立 App 的适配要求。

## 按脚本继承的 APK 安装矩阵

| 目标现状 / 安装结果 | APK 行为 | 数据与应用状态 |
| --- | --- | --- |
| 尚未安装 | 安装；非主用户可先尝试现有包安装关联 | 安装与 UID 查询成功后继续 |
| 备份版本高于已安装版本 | 尝试更新 | 按更新结果和现有安装有效性判断 |
| 同版或已安装版本更高 | 跳过 APK，不强制降级 | 可继续恢复 |
| 两边版本无法比较 | 跳过 APK | 可继续恢复 |
| 更新明确失败，但现有安装与 UID 仍有效 | 记录更新失败，沿用现有安装 | **脚本仍可能继续恢复数据** |
| 首次安装失败、安装信息/UID 无法确认 | 记录失败 | 不写入数据或 AppState |
| 安装提交结果不明（75） | 不重试该 user/package | 本轮禁止数据/AppState；新 App 整批停下对账 |

签名冲突可能落入“明确更新失败、沿用现有安装”的分支，不能写成天然阻断后续数据的保证。计划预览显示备份版本、现有版本、签名检查结果、预计采用的安装策略；若计划允许沿用现有安装，在提交前明确提示“更新失败时可能继续恢复数据”。结果分别记录安装、数据、应用状态，不能把“APK 失败 + 数据成功”简化为完整成功。

未发现自动卸载逻辑；安装参数不包含强制降级。此规则不会保证旧数据与较新应用的数据格式兼容，也不会保证签名不同时数据恢复有意义。首版忠实记录引擎结果，并提供恢复前副本。

## 数据包含与排除

“应用私有数据”不是整份 /data 分区，也不是所有文件逐位镜像。上游 user/user_de 普通路径排除 `.ota / cache / lib / code_cache / no_backup`；部分外部数据路径还排除 `Backup_* / cache / QQ / Telegram`，HMA 特殊分支另有行为。适配层需从实际计划记录排除规则、路径和规则版本；页面不能只写“跳过缓存”或“完整复制”。

备份确认默认安装包 + 私有数据，外部目录按需勾选；应用状态有能力时记录。每个数据组成区分：已包含、未选择、确实为空、不支持、被规则排除、处理失败。记录部分缺失的副本仍可作为可用子集展示，但不能标为所选范围全部完成。

硬件保护密钥、设备绑定凭据、服务端登录状态和系统限制不属于可保证迁移的内容；普通用户看到简明提示，详细原因放在应用详情和恢复预览。

## 存储与网络

- 目的地明确显示协议、名称、路径、连接时刻；“本地”注明仍在手机中，刷机会清除的存储不能被描述为安全离线副本。
- WebDAV 新连接默认 HTTPS；用户可显式选择 HTTP，持续显示未加密传输标记。证书错误不自动忽略，私有 CA 需走明确的信任配置；不自动退回 HTTP。
- SMB 版本、安全特性、容量与重命名行为通过能力探测确定；不自动启用旧协议或声称 SMB 默认加密。凭据错误、权限不足、路径不存在、容量未知分别呈现。
- 用户名/密码不进入备份清单或导出诊断。归档内容首版未加密；传输安全与归档加密是两件事。
- 不在网络故障时偷偷切换目的地；不把空响应当空仓库；不能获取容量时显示未知，采用实际写入错误处理与保守临时空间检查。
- 提交记录的远端状态不明时先回读对账，不能盲目重传覆盖或重复删除。同一 repo 首版单写者，第二台设备不得同时修改；写锁/声明及过期恢复见格式文档。

## 恢复与故障语义

恢复顺序：检查元数据和目标 → 下载当前应用全部必选归档 → 内容 hash 与结构检查 → 保存并确认恢复前副本（如启用）→ 重新校验目标身份/用户 → 安装策略 → 数据写入 → 权限/属主/标签修复 → 可选 AppState → 核验与清理。

归档预检不得解压到真实应用目录；验证路径穿越、链接、大小和文件类型。备份用户 ID 仅作来源信息，不照抄源 UID；目标 UID 从已安装的目标用户/包重新取得。

可判定的应用级失败可继续其他应用；存储中断、Root 丢失、安装结果不明等停止整批。任一已写入部分仍需执行必要收尾，取消不意味着回滚。恢复前副本的“已保存”要求真实提交成功；执行恢复前副本手动恢复时，可明确关闭再次创建副本以免递归。

空间模型区分压缩归档暂存量、最终数据占用增长、保护副本目标容量和安全余量；不能只检查压缩包大小。备份包有解包上限，超过声明与允许预算停止，防止损坏清单或压缩炸弹占满存储。

首次添加原仓库后可重新索引本应用格式；内容校验只能说明相应校验范围通过，不等于能免登录、适用于任意 ROM 或保证目标应用运行正常。
