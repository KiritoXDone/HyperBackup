# 上游格式双向兼容，索引与校验作为附加层

用户确认以和脚本双向兼容为目标：HyperBackup 读取所支持上游版本能读取的备份，新建产物也应由对应原脚本恢复。保留上游根目录、载荷、metadata、特殊数据格式和扫描语义；App 的任务、索引、hash 放在附加层，删除附加数据不影响原脚本恢复。停止以独立 record.json 容器重排上游载荷。

远端同时支持下载后恢复与直接串流恢复，默认采用下载后恢复。串流模式明确展示检查范围，不能承诺完整下载 hash 校验先于覆盖；无匹配 hash 的原脚本备份使用上游可执行的检查，不能因缺少 App 附加文件而拒绝兼容。应用恢复前副本默认开启，可由用户明确关闭，副本失败则不覆盖对应应用。

代价是不能随意改变目录、清理和版本布局，也必须区分不同模式的完整性证据。收益是复用原流程和既有备份，减少长期追上游时的双实现成本。本决定替代 ADR-0003 的“只允许暂存恢复”及原 App 专用容器决定。
