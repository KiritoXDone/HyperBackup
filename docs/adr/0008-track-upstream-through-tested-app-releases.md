# 以完整上游引擎和最小宿主补丁持续跟进

用户确认上游新能力经适配和回归后随 APK 发布，每版锁定 upstream SHA、配套组件、宿主补丁和桥接协议。保留上游业务执行主线，App 不平行重写压缩、安装、传输、特殊应用处理等业务规则；桥接只承担宿主、类型化调用、观察与生命周期边界。

每次更新比较菜单/分发、配置及默认值、Dex/Rust 能力、格式、测试和安全行为，更新覆盖矩阵并运行双向兼容与故障回归，再将候选标为支持版本。上游原始自更新会替换 tools 并可能安装/唤起 SpeedBackup，不能原样用于 HyperBackup；更新入口改为检查和安装经过验证的 HyperBackup APK。

代价是新上游版本不能立刻标为可用；收益是完整能力与受控版本、可追溯验证并存。新功能不依赖运行时拉取 latest，也不因为已嵌入 submodule 就被视作已接入。
